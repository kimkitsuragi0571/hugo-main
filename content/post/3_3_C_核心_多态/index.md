- 静态/动态绑定
  - ![image-1](https://document-image.mubu.com/document_image/32569566_41000099-930f-4994-8472-7fc708d551f1.png?x-tos-process=image/resize,w_220)
    - 子类中写个父类的同名方法
      - 记得返回值前面写个new
      - 要是不写的话,向下转型调用子类同名方法也不报错
        - 打印的是子类方法
      - 因为此时编译器默认隐藏父类方法
        - 其实就相当于子类隐含了new
        - new 关键字的核心作用是： **明确告诉编译器 “我就是要隐藏（hide）父类的同名非虚方法”**
      - ![image-1](https://document-image.mubu.com/document_image/32569566_9f43bba2-9390-427f-a50d-88250729722c.png)
        - 这样就还是打印的父类同名方法
        - 非虚方法遵循 **编译期静态绑定** ：只看引用的声明类型（Person）
    - 但是这里执行的居然是父类方法!和向上转型常识冲突!
      - | 场景 | Father f = new Son() 能否访问？ | 访问到父类 / 子类版本？ | 核心原因 |
        | --- | --- | --- | --- |
        | 父类 public void SpeakName()（普通方法） | ✅ 能访问（因为 public） | 父类版本 | 普通方法静态绑定，按引用类型（Father）找方法 |
        | 父类 public virtual void SpeakName() + 子类 public override void SpeakName() | ✅ 能访问（因为 public） | 子类版本 | 虚方法动态绑定，按实际对象（Son）找重写后的方法 |
        | 父类 private void SpeakName() | ❌ 不能访问（因为 private） | —— | private 修饰符限制，Father 引用也看不见该方法 |
        | 父类 public virtual void SpeakName() + 子类 public new void SpeakName() | ✅ 能访问（因为 public） | 父类版本 | new 切断了虚方法的动态绑定，等同于 “重新定义一个无关的普通方法”，依然按引用类型（Father）绑定父类虚方法 |
      - 父类不能写 private virtual void SpeakName()
        - <mark style="background-color:#fde8e8;">virtual和privte明确冲突,不能一起</mark>
    - 这段其实就是多态
      - 多态vob就是virtual,override,base
      - 静态绑定（编译时绑定）—— 普通方法的调用规则
        - 方法的调用在编译阶段就确定了具体执行哪个类的方法
        - 静态方法属于 **类** ，而非对象
          - 静态方法直接是编译期绑定到类名,不支持运行期调整,不支持任何多态相关修饰符(体现其属于类而非实例)
          - 父类和子类写同名静态方法时， **`只能用 new 关键字标识 “隐藏父类静态方法”`** （无其他语法可选）
            - 可以不写 new—— 语法上完全允许，代码能正常运行，但编译器会抛出 **警告** （提示你 “隐藏父类静态方法” 的行为可能是无意的）；写 new 的核心价值是 **消除警告、明确代码意图** ，而非强制语法要求。
        - ![image-1](https://document-image.mubu.com/document_image/32569566_b37fd90f-1142-486e-847b-ea4d8b5b88a1.png?x-tos-process=image/resize,w_251)
          - 总之父类和子类写了同名方法
            - 用new只是为了避免报错,这里静不静态方法也没有关系
            - 此时是优先调用声明类型的方法
              - 所谓编译阶段确定
              - Person stu = new Student();
                - 调用的就是Person的同名方法
              - ![image-1](https://document-image.mubu.com/document_image/9bb068ff-878d-4ce3-8ce5-f80e6c8acd31-32569566.jpg?x-tos-process=image/resize,w_400)
                - 霍霍Student stu = new Person();这种写法当然是本身就不合法的
                - 向下转型其实也用到了静态绑定,毕竟编译期申明为Student类型了嘛
      - 动态绑定（运行时绑定）—— 虚方法的调用规则
        - 改成看运行阶段实例是哪个,并调用实例类型的方法
        - ![image-1](https://document-image.mubu.com/document_image/32569566_c154f379-1f39-44ea-9d06-95e53bc391a4.png?x-tos-process=image/resize,w_374)
          - 一般来说都是配套使用的(不配套也没啥场景用得上)
            - 父类中写个virtual
            - 子类中写个override
              - 孙子中同样可以继续重写
          - ![image-1](https://document-image.mubu.com/document_image/32569566_4bb2d6e8-ddf7-4c92-ce5f-85cc41746c90.png?x-tos-process=image/resize,w_400)
            - 总之优先调用实例对象了
          - virtual 虚方法的核心前提是「子类能 **访问并重写** 该方法」
            - 所以用个private就不行了
      - 方法重写（Override）—— 子类替换父类虚方法的实现
        - <mark style="background-color:#fde8e8;">注意静态类全都没法被重写</mark>
        - 静态方法属于「类本身」，不依赖对象实例，调用时直接绑定到「编译时的类名」，根本没有 “运行时动态选择” 的过程
      - 方法隐藏（Method Hiding）—— 子类新建同名方法
      - 向上转型的权限限制 —— 引用类型决定 “可见范围”
- 抽象类和抽象函数
  - 抽象类
    - ![image-1](https://document-image.mubu.com/document_image/32569566_c96b4756-db0f-4b55-b4c3-d82f407103f6.png?x-tos-process=image/resize,w_367)
    - 声明
      - ![image-1](https://document-image.mubu.com/document_image/f0c3d887-12bd-4806-9cd0-7bce1099f77e-32569566.jpg)
        - 内部
          - 可以写抽象函数
          - 抽象类和静态类不能作为内部类,只能写在命名空间下,所以不能包含
        - 继承
          - 静态类同样不能继承自抽象类
    - 调用
      - ![image-1](https://document-image.mubu.com/document_image/32569566_807e0547-1479-425a-c07a-5b4e7a114315.png?x-tos-process=image/resize,w_261)
        - 无法被实例化,因为"生物只是中抽象的概念"
          - 要实例化也得指明哪种哪个具体的生物
        - 这里还是可以用向上转型的哈
  - 抽象函数
    - ![image-1](https://document-image.mubu.com/document_image/32569566_51003d64-a25a-4c60-ac96-80bd653d1a1b.png?x-tos-process=image/resize,w_400)
      - 抽象方法没有{}方法体
        - ![image-1](https://document-image.mubu.com/document_image/32569566_d7eed622-389b-4532-f921-d1d5a4aa482d.png?x-tos-process=image/resize,w_267)
      - 和虚方法virtual一样,必须让子类能继承并重写
      - ![image-1](https://document-image.mubu.com/document_image/32569566_5d1113c5-1c29-4ceb-b44d-b10f6d4346d8.png?x-tos-process=image/resize,w_400)
        - 继承的子类点一下,就能自动帮你补全重写方法
      - 和抽象abstract函数冲突的修饰符
        - private
          - 子类没法访问重写
        - sealed
          - 子类没法访问重写
        - virtual
          - 抽象函数本来就是隐含虚方法,冗余
        - static
          - 抽象函数是实例级,静态则是类级
          - C#11之后仅限接口 / 抽象类的静态多态可以用
            - 普通抽象函数仍然不能用static
    - 虚方法和抽象方法
      - 抽象方法一定没有{}函数体,虚方法有{}且其中可以不写逻辑
      - 虚方法可以由子类选择性实现,抽象方法必须实现
        - 就是之前说的写了virtual可以不写override
        - ![image-1](https://document-image.mubu.com/document_image/32569566_08123528-d4f9-4af5-8580-5f560a3fea2f.png?x-tos-process=image/resize,w_234)
          - 这里抽象方法已经在子类中实现,所以孙子类不写也不报错
      - 抽象方法必须放在抽象类中
        - 而抽象类中则可以写虚方法
      - 二者都可以被子类无限重写
- 接口
  - 规范
    - 关键字是interface
    - ![image-1](https://document-image.mubu.com/document_image/07b4babf-2072-4cd0-87d0-d34f96c19eed-32569566.jpg?x-tos-process=image/resize,w_311)
      - 接口成员的限制
        - 接口可包含的有
          - 抽象方法
          - 抽象属性
          - 事件
          - 索引器
          - 静态抽象成员
            - C#11之后少有的static配抽象的情况
          - 默认实现
        - 接口不能包含的有
          - 成员变量
          - 普通方法
          - 静态 变量/方法/构造函数
          - 构造/析构 函数
          - private/protected/sealed 成员
        - ![image-1](https://document-image.mubu.com/document_image/32569566_965a1288-7e64-4156-acd8-48ba1c186239.png?x-tos-process=image/resize,w_500)
          - 总之只能定规矩,不能存数据,不能做实现
          - 也不能限制访问范围
  - 声明
    - ![image-1](https://document-image.mubu.com/document_image/32569566_7adc0b03-37f0-4f43-9b51-2fe33eb8bf69.png)
      - 命名
        - 大写I加上帕斯卡
        - 对比枚举缺少_符号
      - 成员
        - 不能有成员变量
        - 只能有方法/属性/索引/事件
          - 当然索引和事件我们还没学
      - 修饰符
        - 不写,默认是public
          - 但是C#8.0以前,这里是不能显式加public的
        - 不能是private
          - 同样是因为类继承接口后要实现接口中所有成员
          - 和抽象方法有点像
      - 成员不能被实现
        - ![image-1](https://document-image.mubu.com/document_image/32569566_4d41300e-17c3-4f7a-b750-c10d9304d681.png?x-tos-process=image/resize,w_93)
          - 所以方法不能有{}代码块
          - 属性中get和set也不能有,只能像自动属性一样
    - 类继承接口
      - ![image-1](https://document-image.mubu.com/document_image/32569566_09009109-5b67-4bbe-c754-7b62480c14c4.png)
        - 接口中写成员属性直接写就行
        - 普通的成员属性你还得先写个同名成员变量
          - 好吧其实也可以不写,像Info那种直接调用
      - ![image-1](https://document-image.mubu.com/document_image/fd2881b6-9629-4c8f-a4b6-e1ef9a4a8c9b-32569566.jpg?x-tos-process=image/resize,w_400)
        - 类可以继承1个类和多个接口
        - 这里右键就可以快速补全了
      - 正式写法
        - ![image-1](https://document-image.mubu.com/document_image/32569566_0cff40c0-bd34-43f4-a57e-a31805cf9cb9.png?x-tos-process=image/resize,w_311)
        - ![image-1](https://document-image.mubu.com/document_image/a4a68530-85c4-44e4-954c-9f9ef62eee8f-32569566.jpg?x-tos-process=image/resize,w_316)
          - 说人话就是接口中定下所谓"契约"
            - 也就是规则
            - 继承了这个接口的子类来补全接口成员的实现逻辑
          - 并且子类中补全的成员默认且强制是public的
            - protected基本是用不上
            - 主要是为了避免导致 “接口承诺公开可调用，但子类藏成私有” 的矛盾
          - 还可以加上虚方法
            - ![image-1](https://document-image.mubu.com/document_image/32569566_37ab1c9d-16c7-453d-fa5c-6e26c27431a0.png?x-tos-process=image/resize,w_313)
              - 这下Student的子类还可以重写补全的实现
              - 注意继承接口只是实现其规则,不需要加上override
                - 子类继承父类的时候重写方法才需要override
          - ![image-1](https://document-image.mubu.com/document_image/32569566_53318e35-a448-4dcf-8a62-b687455eab90.png?x-tos-process=image/resize,w_400)
            - 接口继承接口时,不用写实现
            - 类继承接口的时候再把实现写全
            - ![image-1](https://document-image.mubu.com/document_image/32569566_fafd6dfc-c644-45f0-f3ed-42172986c205.png?x-tos-process=image/resize,w_400)
              - 向下转型的时候就可以三个接口都当成父类
