- 特殊文件夹
  - Asset文件夹
    - 路径获取
      - `print(Application.dataPath);`
        - 只是用来获取Asset文件夹的路径,没了
      - 仅编辑模式下使用,游戏发布就没了
  - Resources资源文件夹
    - 路径获取(没卵用)
      - `print(Application.dataPath + "/Resources");`
        - 一般也不会获取这个文件夹路径
        - 因为没法通过路径读取Res文件夹中的文件
      - <mark style="background-color:#fef3c7;">路径拼接的含义</mark>
        ![路径拼接的含义-1](https://document-image.mubu.com/document_image/32569566_55568feb-6883-4fad-fbca-75f2a8553d49.png?x-tos-process=image/resize,w_221)
        - 这里+就是获取XX文件夹下面的拼接文件夹
    - <mark style="background-color:#fef3c7;">会全被打包进安装包,所以一般只会把需要动态加载的资源放入该文件夹</mark>
    - 一般只能用Resources.Load这类专用 API 来加载
      - `Resources.Load("文件名");`
      - 不能用路径来读取Res中文件哈
  - StreamingAssets 流动资源文件夹
    - 路径获取
      - `print(Application.streamingAssetsPath);`
        - 获取路径不需要拼接,直接写Application.StreamingAssets
      - `print(Application.dataPath + "/StreamingAssets");`
        - 千万别用路径拼接,因为打包后这个文件夹在不同平台上路径不同
    - 同样需要手动创建
    - 对比普通Res文件夹,不会被压缩加密只能用API,可以自由操控
    - 移动平台只读,但是PC可读可写???
  - persistentDataPath 持久数据文件夹
    - 路径获取
      - `print(Application.persistentDataPath);`
        - 放在固定路径,而且打包后不同平台路径也不同
    - <mark style="background-color:#fef3c7;">没法手动创建</mark>
    - 所有平台都可读写
  - 补充文件夹
    - Plugins 插件文件夹
      - 同样需要手动创建
      - 一般不获取路径
    - Editor 编辑器文件夹
      - 同样需要手动创建
      - 一般不获取路径
        - 硬要获取 可以用工程路径拼接
        - `print(Application.dataPath + "/Editor");`
    - 默认资源文件夹 Standard Assets
      - 手动创建(或者你导入了就有这个资源)
      - 默认资源文件夹,代码和资源优先被编译
      - 现在做商业项目也用不上了
- Res资源加载
  - Res同步加载
    - 加载Res下的文件
      - 加载某一文件
        - `Sprite sprite = Resources.Load<Sprite>("图片名");`
          - 注意这里也不能带上文件后缀名哈
        - `AudioClip clip = Resources.Load<AudioClip>("音频名");`
      - 如果有子文件夹
        - `GameObject btn = Resources.Load<GameObject>("UI/Button");`
    - 使用获取的文件
      - <mark style="background-color:#fef3c7;">预制体实例化后才能在在场景中出现</mark>
        - `GameObject prefab = Resources.Load<GameObject>("Player");`
          - 这里只是将配置加载都内存中,然后用一个引用指向它
        - `GameObject realPlayer = Instantiate(prefab);`
        - `realPlayer.name= "我是新生成的Cube";`
        - 或者你也可以一次性写
          - `GameObject pre = Instantiate(Resources.Load<GameObject>("Cube"));`
      - 其他的组件获取直接使用就行
        - ![image-1](https://document-image.mubu.com/document_image/32569566_043a2c51-30b1-4d32-ee54-e8eda93d7b16.png?x-tos-process=image/resize,w_400)
          - 一般是场景中创建AudioSources,然后把音频文件拖动到AudioClip中,你这里赋值给播放器的clip就完事了
          - 同样只是获取引用并不会播放
        - ![image-1](https://document-image.mubu.com/document_image/32569566_72daac6f-ad75-49a2-c42f-edbc327078b9.png?x-tos-process=image/resize,w_400)
    - 注意事项
      - <mark style="background-color:#fef3c7;">前面也反复提过,不能直接路径获取,只能Resources.Load</mark>
        - 不用泛型就是返回默认的Object类型,我都懒得写了,没用的东西
      - Res文件夹位置不限,个数可以多个
        - 甚至不同文件夹里还可以有重复成员
        - 但是没啥用Load只会随机加载其中一个,导致错乱
      - 解决重名不同文件(但是我们用泛型方法,都不用考虑这种问题)
        - `tex = Resources.Load("Tex/TestJPG", typeof(Texture)) as Texture;`
        - `ta = Resources.Load("Tex/TestJPG", typeof(TextAsset)) as TextAsset;`
  - Res异步加载
    - 概念
      - 就是内部新开一个线程加载资源,避免主线程卡顿
      - 异步性
        - 拿到的资源不能马上用(至少等一帧),所以叫异步加载
      - 原子性
        - 新线程加载的资源不能中途加载到一半拿出来用
      - <mark style="background-color:#fde8e8;">新开的线程不能访问Unity</mark>
        - 总之通过中间商对象来交流
    - 使用
      - `ResourceRequest rq = Resources.LoadAsync<texture>("Disco");`
        - 提交加载请求,进度通过rq对象来监视
        - 配合OnGUI中语句,texture没有加载完毕的时候不能使用
          - ![image-1](https://document-image.mubu.com/document_image/32569566_c37ca48c-0263-47a5-f814-ac063d5eea94.png?x-tos-process=image/resize,w_307)
      - `rq.completed += (AsyncOperation rq) => { print("加载完毕");};`
        - 1.当资源加载完毕,Unity自动调用completed事件
          - 为什么是加载完毕自动调用呢?底层的事你不需要搞那么明白
        - 2.传入的参数就是监视对象rq
          - AsyncOperation是父类容器,能装下多种子类监视对象
            - <mark style="background-color:#fde8e8;">场景加载 AsyncOperation</mark>
            - <mark style="background-color:#fde8e8;">资源加载 ResourceRequest</mark>
            - <mark style="background-color:#fde8e8;">网络请求 UnityWebRequestAsyncOperation</mark>
          - 传入对象rq才能判断是哪个加载请求已经完成
            - 比如有rq1,rq2等多个异步加载请求
      - AsyncOperation类中属性
        - completed事件就是刚才讲的,自动执行加载完成的方法
        - 检查加载是否完成
          - `if(rq.isDone)`
        - 显示0~1进度
          - `void Update(){Debug.Log(rq.progress);}`
        - 场景异步加载完毕也不会进入
          - `AsyncOperation op = SceneManager.LoadSceneAsync("Game");`
            - <mark style="background-color:#fde8e8;">注意这里父类AsyncOperation,也负责场景加载</mark>
            - <mark style="background-color:#fde8e8;">子类ResourceRequest只是资源加载</mark>
          - `op.allowSceneActivation = false;`
    - 详细例子
      - 1.首先ResourceRequest 类的声明
        - 异步加载必须通过.asset属性获取资源
          - ![image-1](https://document-image.mubu.com/document_image/32569566_657b641e-e307-4536-a31d-dd52d236cfd2.png?x-tos-process=image/resize,w_297)
        - 但是直接同步调用asset属性不能获取
          - ![image-1](https://document-image.mubu.com/document_image/32569566_b6b9b15a-d336-4842-fc78-32588bf83ed9.png?x-tos-process=image/resize,w_342)
      - 2.completed事件调用的函数
        - ![image-1](https://document-image.mubu.com/document_image/32569566_b73b7ef9-e28f-4bd9-951a-c8e93231cdf7.png?x-tos-process=image/resize,w_297)
          - **父类：AsyncOperation**
          - **子类：ResourceRequest**
        - 当加载完毕时,向下转型调用rq的asset属性,然后转化为对应Texture
  - Res卸载资源
    - <mark style="background-color:#fde8e8;">ctrl+7 profiler窗口打开性能检测</mark>
    - 加载的资源会放在内存中
      - 重复加载不会浪费内存(直接取出来)
      - 但是浪费性能,因为每次加载都会去查找取出
    - 卸载指定资源
      - 卸载单个资源不需要配合GC
      - <mark style="background-color:#fde8e8;">不能用于卸载GameObject,即使没有Instatiate实例化也不能卸载</mark>
      - `Sprite dis = Resources.Load<Sprite>("Disco");`
      - `Resources.UnloadAsset(dis);`
    - 卸载未使用的资源
      - 卸载未使用资源可以配合GC,一般过场时和GC一起用
      - `Resources.UnloadUnusedAssets()`
      - `GC.Collect ()`
  - 场景同步加载
    - `SceneManager.LoadScene("DlcScene");`
      - 使用前要把场景放进列表
    - 切换时会删除当前场景所有物体,加载下一个场景信息
      - 可能很耗时,所以用异步加载
  - 场景异步加载
    - 使用
      - `AsyncOperation op = SceneManager.LoadSceneAsync("Game");`
        - <mark style="background-color:#fde8e8;">注意这里父类AsyncOperation,也负责场景加载</mark>
        - <mark style="background-color:#fde8e8;">子类ResourceRequest只是资源加载,所以不能用子类容器装填</mark>
      - `op.completed += (AsyncOperation op) =>{};`
        - 同样的,记得写事件的参数
        - 同样不能.asset同步使用,需要用事件异步加载
      - 加载完毕不进入该场景
        - `op.allowSceneActivation = false;`
    - 用事件回调,切换场景时会报错
      - 1.当删除物体
        - 1.当场景里 Destroy(物体),面板上消失,但是内存中仍然存在
        - 2.等到Unity 自动 GC 垃圾回收 才会真正清掉内存
        - 3.但即使GC回收清理掉内存,函数仍然在事件中
          - 比如Cube物体,脚本上有Speak方法
          - `op.comleted+=Cube.Speak;`
          - 当物体被回收,Speak方法仍然在事件列表中
        - <mark style="background-color:#fde8e8;">4.触发事件就会调用已销毁物体的方法,导致报错</mark>
      - 2.当切换场景
        - 加载场景会把当前场景没有特别处理的对象都删除
        - 就会导致上述的错误
      - 3.避免上述错误
        - `DontDestroyOnLoad(this.gameObject);`
          - 过场景时不移出该脚本依附对象
          - 一般写在Awake里面
    - 协程则不会因为切换场景报错
      - 协程依附obj被销毁只是停止运行,而不会报错
    - 进度条制作
      - 利用异步加载(不准确也不咋用)
