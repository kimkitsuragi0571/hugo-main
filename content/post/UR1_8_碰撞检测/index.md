- 刚体
  - 碰撞产生的必要条件
    - 两个物体都有碰撞体
    - 至少一个物体有刚体
      - 刚体就是让obj受到物理效果的影响
  - 核心参数
    - Mass（质量，默认 1）
      - Mass,重量大,碰撞体积箱重合的时候产生的力就不够推动了
      - 下落速度和物体质量无关
        - 坏了我成亚里士多德了
    - Drag（空气阻力）
      - Drag,就是空气阻力,阻力大了下落都慢
    - Angular Drag（角阻力）
      - AngularDrag,就是真空里面东西被撞了会旋转(宇航员),这个阻力大了就转不起来
        - 测试的时候关掉重力,然后直接碰撞
    - Is Kinematic（是否运动学）
      - 选了这个重力选项肯定自动失效失效
      - 勾选后不受物理影响，不能通过力移动
        - 专门用来做碰撞检测
      - ![image-1](https://document-image.mubu.com/document_image/32569566_9f865133-34cf-46a8-c85a-d7514e296701.png?x-tos-process=image/resize,w_400)
        - 所以用代码移动"不会动的墙",会导致不停重新计算,很卡
        - 所以这里还是得用刚体,没法直接只加个碰撞器,从而替代运动学的作用
    - Interpolate（插值）
      - 不勾选物体有卡顿感
      - 之前设置里面可以设置物理帧更新时间(FixedUpdate)
        - 间隔改的大点,才能看出插值运算的作用
        - <mark style="background-color:#fef3c7;">注意物理帧间隔过大,导致碰撞的时候直接穿过去</mark>
    - Constraints（约束）
      - Freeze Position：冻结物体 XYZ 轴上的移动;
      - Freeze Rotation：冻结物体 XYZ 轴上的旋转
    - Collision Detection（碰撞检测）
      - 就是为了避免上面的那种子弹穿墙的情况
      - 总之记住最下面的性能消耗关系就对了

  - 物理材质
    - 创建
      - 场景或者Asset里面点击创建Physical Material,然后拖动到碰撞器的Material关联
      - 注意测试的时候Cube和平面都要添加材质
        - 一方添加就可以生效,两个都加更加精准
    - 参数
      - Dynamic Friction
        - 移动时的摩擦力
        - **0** ：极度光滑（如冰面）； **1** ：迅速刹车（如粗糙沙地）
      - Static Friction
        - 静止时的摩擦力
        - **0** ：静止即滑动； **1** ：极难推动（如粘住的物体）
      - Bounciness
        - 决定碰撞后反弹能量
          - 比如蹦床是不是会逐渐损失高度
        - **0** ：完全不反弹（落地即停）； **1** ：完美弹性（无能量损失）

- 碰撞检测函数
  - 补充
    - <mark style="background-color:#fef3c7;">碰撞和响应触发函数属于特殊的生命周期函数,同样是反射自动调用</mark>
      - 就是一碰撞就找碰撞检测函数的名字,自动调用
    - <mark style="background-color:#fde8e8;">可以把碰撞检测和触发检测都写成虚方法,子类中自动调用</mark>
      - <mark style="background-color:#fef3c7;">Unity 调用父类的虚方法时，会自动跑到子类重写的方法里执行</mark>
        - ![image-1](https://document-image.mubu.com/document_image/32569566_90da20aa-f045-4406-f5f6-8a0fed636b57.png?x-tos-process=image/resize,w_254)
        - ![image-1](https://document-image.mubu.com/document_image/32569566_e0e3248f-943c-4e6a-87bb-fb77f82e94d4.png?x-tos-process=image/resize,w_278)
      - 1.首先Unity一个脚本只能有一个类
        - 其余和脚本不同名的类根本不执行,也就没有意义了
        - 所以如果一个Person脚本里有Person类和Student继承,就没有这个效果
          - Student类并不执行
          - 而且Person已经继承了Mono类,写成继承Student来实现也不行
      - 2.正确的写法是分为两个脚本且只挂载子类Student脚本
        - Unity能直接在Assets里面找到父类Person脚本
        - Student脚本继承了Person的所有可继承功能
      - 3.如果都挂载在同一个物体
        - 两个脚本会重复执行
        - Person调用自身,Student调用父类/自身
      - 4.如果各自挂载在两个不同的物体
        - 比如Person物体碰撞,Student脚本并没有反应
        - Student物体发生碰撞,打印父类/子类碰撞函数
          - <mark style="background-color:#fef3c7;">但是Person脚本本身并没有执行</mark>
    - <mark style="background-color:#fef3c7;">刚体在父物体上 → 碰撞 / 触发消息只会发给父物体上的脚本</mark>
      - Cube(只有刚体)下我挂载个Sphere(只有碰撞器),和Capsule发生了碰撞
      - Sphere挂载的脚本上碰撞/检测函数,并不会实现
      - 反正脚本需要挂载到父物体上就对了
  - 碰撞检测
    - OnCollisionEnter
      - 碰撞时执行函数
        - `private void OnCollisionEnter(Collision collision)`
          - <mark style="background-color:#fef3c7;">collision就是碰到的另一个对象的信息</mark>
      - 可以得到碰撞对象的所有信息
        - 碰撞到的对象碰撞器的信息
          - `collision.collider`
        - 碰撞对象的依附对象（GameObject）
          - `collision.gameObject`
        - 碰撞对象的依附对象的位置信息
          - `collision.transform`
        - 触碰点个数
          - `collision.contactCount`
        - 接触点 具体的坐标
          - `ContactPoint[] pos = collision.contacts;`
            - 因为一次碰撞有多个接触点嘛
    - OnCollisionStay
      - 模型重合就一直调用
        - `private void OnCollisionStay(Collision collision)`
    - OnCollisionExit
      - 碰撞结束分离时会自动执行
        - `private void OnCollisionExit(Collision collision)`
  - 触发检测
    - <mark style="background-color:#fde8e8;">Collider</mark>
      - Collider相当于所有碰撞器的基类
        - 所以父类容器可以装所有种类的碰撞器
        - `Collider col;`
        - `col = GetComponent<BoxCollider>();`
        - `col = GetComponent<SphereCollider>();`
      - 和Collision的区别
        - <mark style="background-color:#fce7f3;">Collider:是一个具体的碰撞器组件</mark>
        - <mark style="background-color:#fce7f3;">Collision：碰撞信息，是数据，只在碰撞函数里出现</mark>
          - `Collider myCollider = GetComponent<Collider>();`
      - <mark style="background-color:#fce7f3;">为什么碰撞检测用Collision类型参数,触发检测用Collider类型参数</mark>
        - 碰撞检测有物理碰撞、反弹、受力 → 需要一整套完整碰撞信息
        - 触发检测只是穿过检测，没有物理效果,只需要知道 “谁碰到我了”
          - 拿到 Collider → 就能拿到物体、拿到标签、拿到组件
          - 而且也不能用Collision
            - Trigger 没有物理碰撞,没有 Collision 数据
        - 总之<mark style="background-color:#fce7f3;">碰撞需要物理信息,触发只需要知道有没有带组件的物体传进来</mark>
    - OnTriggerEnter
      - `private void OnTriggerEnter(Collider other)`
    - OnTriggerExit
      - `private void OnTriggerExit(Collider other)`
    - OnTriggerStay
      - `private void OnTriggerStay(Collider other)`
- 刚体加力
  - 刚体自带加力的方法
    - 首先应该获取刚体组件
      - `Rigidbody rigidBody = this.GetComponent<Rigidbody>();`
        - Component类中自带有rigidbody属性,不过是个已经过期的属性没法用
        - <mark style="background-color:#fde8e8;">所以</mark>`private Rigidbody rigidbody; rigidbody = GetComponent<Rigidbody>();`<mark style="background-color:#fde8e8;">是错误写法</mark>
    - 移动
      - 添加世界坐标系的力
        - ![image-1](https://document-image.mubu.com/document_image/32569566_ebc5ad00-9118-4543-99af-625f0ee93f6a.png?x-tos-process=image/resize,w_326)
          - 注意这种写法是错误的,rb只是start里面的局部变量
        - ![image-1](https://document-image.mubu.com/document_image/32569566_489b7468-c811-408e-ccf9-8405b172adfc.png?x-tos-process=image/resize,w_323)
          - 直接在类中写 `rb = GetComponent<Rigidbody>();`也会报错
          - 正确写法是变量声明写在类中,赋值写在start内部
            - rb赋值后在Update里面当然也是可以用的
        - `rigidBody.AddForce(Vector3.forward * 10);`
          - 添加后如果没有阻力,物体一直匀速运动
          - 阻力在面板 Drag 中修改，在 Update 中调用可在有阻力时持续移动
      - 添加局部坐标系的力
        - 世界坐标系 + 自身transform.forward
          - `rigidBody.AddForce(this.transform.forward * 10);`
        - AddRelativeForce 相对本地坐标
          - `rigidBody.AddRelativeForce(Vector3.forward * 10);`
    - 添加扭矩力使其旋转
      - 相对世界坐标
        - `rigidBody.AddTorque(Vector3.up * 10);`
      - 相对本地坐标
        - `rigidBody.AddRelativeTorque(Vector3.up * 10);`
    - 爆炸效果加力
      - `rigidBody.AddExplosionForce(100, Vector3.zero, 10);`
        - 爆炸效果第一个参数是爆炸大小,第二个是爆炸中心
        - <mark style="background-color:#fef3c7;">多个Cube堆一块模仿爆炸,那么得每个物体都添加脚本</mark>
          - <mark style="background-color:#fef3c7;">这个爆炸效果不是直接影响全局</mark>
          - 闫芳太极拳资道吧
        - 不要放在Update里面,每帧炸一次,全部炸上天
        - 还有个重载可以给物体指定点添加力,不过暂时用不上
    - 直接改变速度
      - `rigidBody.velocity = Vector3.forward * 5;`
        - Translate是直接改位置,这个是直接改速度
      - `rigidBody.velocity = transform.forward * 5;`
        - 这样就是变相实现朝着局部坐标系移动了
  - 力的几种模式
    - ![image-1](https://document-image.mubu.com/document_image/32569566_55442afb-1fd4-4a94-bc4c-3990a64b86b4.png?x-tos-process=image/resize,w_270)
      - 注意是乘以模式参数,而不是第二个参数
    - 加速模式
      - `r.AddForce(Vector3.forward* 1 *ForceMode.Acceleration);`
        - 加速度恒定,忽略物体质量
        - 适合角色移动、恒定加速
    - 力模式
      - `r.AddForce(Vector3.forward* 1 *ForceMode.Force);`
        - 给物体一个持续的力,与其质量有关
        - 符合真实物理，质量越大，加速度越小，适合模拟真实受力（如推箱子
        - 默认模式
    - 冲量模式
      - `r.AddForce(Vector3.forward * 10, ForceMode.Impulse);`
        - 给物体添加一个瞬间的力，与其质量有关
        - 适合跳跃、爆炸、冲击等一次性受力场景
        - <mark style="background-color:#fef3c7;">忽略时间（默认 t=1）</mark>
          - 正常力都是按照,t = 0.02 秒(一帧)计算,要一直推才会动
            - 像持续加油门
          - 冲量模式直接推 1 秒的量
            - 就相当于把力持续一秒的冲量攒起来,一瞬间打出
        - <mark style="background-color:#fde8e8;">start中一瞬间加力让物体移动,直接写Force模式没用(因为只加了一瞬间),需要用Impulse模式</mark>
    - 速度变化模式
      - `r.AddForce(Vector3.forward*10*ForceMode.VelocityChange);`
        - 给物体添加一个瞬时速度，忽略质量
        - 直接给物体叠加速度，无视质量，适合瞬间加速、瞬移等场景
        - <mark style="background-color:#fef3c7;">和冲量模式一样忽略时间</mark>
  - 力场
    - Constant Force组件
      - 添加个Y轴上的力就可以抵消重力
      - 也可以给扭矩的力,让物体一直转
      - 额,作用就是让你不用写脚本
