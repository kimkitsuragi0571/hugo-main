- Object中的各种方法
  - `ReferenceEquals(a, b)`
    - 仅判断 **内存地址** （对象身份）
    - <mark style="background-color:#fef3c7;">完全无视 Equals 重写</mark>
      - 是判断 “是否为同一个对象” 的唯一可靠标准
      - 说人话就是不会内部调用a.Equals(b);只是判断地址
        - 对比下面的Equals(a,b)就知道了
    - 值类型永远返回 false
      - 装箱后必定生成不同引用对象
  - `Object.Equals(a, b)`
    - 静态方法,所以是类名调用
    - 判断 “内容相等”
      - <mark style="background-color:#fef3c7;">值类型默认比较所有字段值</mark>
      - <mark style="background-color:#fef3c7;">引用类型默认比较内存地址</mark>
        - 可重写实例 Equals 改变规则
    - <mark style="background-color:#fef3c7;">规则是先判空，再调用a.Equals(b)（实例方法）</mark>
      - <mark style="background-color:#fef3c7;">两个Equals</mark>
        - <mark style="background-color:#fef3c7;">这个静态版(有两个参数的)就是多了个判空,然后调用实例版</mark>
          - <mark style="background-color:#fef3c7;">相当于多了个壳</mark>
        - <mark style="background-color:#fef3c7;">下面那个虚方法中的实例版</mark>
    - 语法
      - 可省略Object.，但作用域有同名 Equals 时需显式加
      - <mark style="background-color:#fef3c7;">值类型传入自动隐式装箱，无需手动处理</mark>
  - `GetType()`
    - 返回 **运行时实例的真实类型** （无视编译期声明类型）
      - 反射场景常用
  - `MemberwiseClone()`
    - protected 方法（外部无法直接调用）
    - 实现对象 **浅拷贝**
      - <mark style="background-color:#fce7f3;">值类型：拷贝后数据相同，栈存储位置不同（深浅拷贝结果一致）；</mark>
      - <mark style="background-color:#fce7f3;">引用类型：浅拷贝仅复制栈上指针（堆中实例共用），深拷贝需自定义（指针和堆实例均不同）；</mark>
    - 使用
      - 需在 public 方法中，通过return MemberwiseClone() as 目标类型转换
        - （因返回值为 Object 类型）
  - Object中的虚方法

- StringBuilder
  - 特性
    - String比较特殊,更改引用会在堆中创建一个新的对象,浪费空间
      - StringBuilder就是为了解决这个问题
    - 需提前导入 System.Text 命名空间
  - 初始化
    - `StringBuilder sb = new StringBuilder("初始内容");`
      - 不能直接指定,必须new实例化对象
      - StringBuilder str ="123"报错
  - 容量
    - 查看容量
      - `int capacity = sb.Capacity;`
    - 数组不能动态扩容
      - 比如1000个字符,你只写了10个
        - 后面增加的时候就是往那剩下的9990个空位里放
          - 始终是原来的那个对象
        - 但是超出容量了,那还是得扩容
          - 此时需要复制一个新的数组来放置
          - 又变成普通数组那种频繁搬家了(原来的数组变成垃圾)
          - 所以别超容量
      - 所以StringBuilder提前有预留空出来的容量
    - 优点
      - 垃圾回收比较少,代价就是比较浪费空间
  - 操作
    - 增/拼接
      - `sb.Append ("新增的字符串内容")`
      - `sb.AppendFormat ("格式化内容：{0}，{1}", 123, "测试")`
        - 普通字符串可以str+="123"
        - StringBuilder不行
          - 要用str.Append("123")
          - 或者AppendFormat
    - 插
      - `sb.Insert (0, "在索引 0 位置插入的内容")`
    - 删
      - `sb.Remove (2, 5)`
      - `sb.Clear ()`
    - 查
      - `int findIndex = sb.ToString ().IndexOf ("要查找的内容")`
      - `int findLastIndex = sb.ToString ().LastIndexOf ("反向找的内容")`
    - 改(指定索引字符)
      - `sb [3] = ' 新字符'`
    - 替换
      - `sb.Replace ("旧字符串", "新字符串")`
      - `sb.Replace (' 旧字符 ', ' 新字符 ')`
    - 清空后新增
      - `sb.Clear ().Append ("重新赋值的内容")`
    - 判断相等
      - `bool isEqual = sb.Equals (new StringBuilder ("要对比的内容"))`
        - 不能用普通字符串的==
        - 同样用Equals方法

- 抽象类和接口的区别
  - ![image-1](https://document-image.mubu.com/document_image/32569566_f901e211-351e-4790-9e3c-1a008134b2a1.png?x-tos-process=image/resize,w_400)
    - 相同点
      - 还算熟悉,看图罢
    - 区别
      - <mark style="background-color:#fde8e8;"> **构造函数** </mark><mark style="background-color:#fde8e8;">：抽象类中可以有构造函数；接口中不能。</mark>
      - **继承限制** ：抽象类只能 **单一继承** ；接口可以被 **多个继承** 。
      - **成员变量** ：抽象类中可以有成员变量；接口中不能包含成员变量。
        - 哦对的对的,只是不存在抽象变量这种东西
      - **方法种类** ：抽象类中可以声明成员方法、虚方法、抽象方法、静态方法
        - 接口中只能声明 **未实现的抽象方法** 。
      - **访问修饰符** ：抽象类方法可以使用访问修饰符；接口一般不写访问修饰符,默认 public
        - 子类补全契约也得是public
    - 概念上
      - 抽象类表示is
      - 接口表示是否能做到
