- 概念
  - 创建UI的时候必定自动创建Canvas和EventSystem
  - 所有组件都依赖于这两个对象
- 依附于Canvas的组件
  - `Canvas(画布组件)`
    - 主要用于渲染自己的所有UI子对象
      - 不是Canvas的子对象就不能被渲染
      - 可以在Canvas设置UI渲染方式
      - 场景中可以有多个Canvas负责不同的渲染规则(很少用)
    - `RenderMode(渲染模式)`
      - 通用选项
        - `PixelPerfect(像素完美)`
          - 降性能提效果
        - `SortOrder(排序顺序)`
          - 多个Canvas时的渲染层级(谁在谁上面)
        - `TargetDisplay(目标显示器)`
          - 多个屏幕时,UI渲染到哪个显示器
          - 3DS是吧
        - `AdditionalShaderChannels(附加着色器通道)`
          - 读取着色器相关数据,暂时不学而且做UI也用得少
        - `Vertex Color Always In Gamma(顶点颜色总是用伽马)`
          - 强制让 UI 的顶点颜色，始终按 Gamma 色彩空间处理,颜色更亮
      - `ScreenSpace-Overlay(屏幕空间-覆盖模式)`
        - UI始终渲染挡在所有物体最前方，不受相机影响
        - 前两种模式Canvas的位置大小由相机决定,手动没法改
          - (相机模式有个Distance勉强算是可以改吧)
      - `ScreenSpace-Camera(屏幕空间-相机模式)`
        - UI可被3D物体遮挡
          - 比如模型展示在UI之前就用的上?
        - `RenderCamera(渲染相机)`
          - 用于渲染UI的摄像机，如果不设置就和Overlay模式一样
          - 一般只会让部分3D物体在UI前面,设置为MainCam就全在前面了,不推荐
          - <mark style="background-color:#fef3c7;">专门设置个相机渲染UI</mark>
            - <mark style="background-color:#fce7f3;">这里不还是实现的物体固定在UI下面显示吗</mark>
              - <mark style="background-color:#fce7f3;">UI相机层级设置为0,CullingMask设置为仅UI,,并且选择DepthOnly</mark>
              - <mark style="background-color:#fce7f3;">MainCam层级设置为-1,CullingMask排除UI</mark>
            - <mark style="background-color:#fce7f3;">但是这里就有所不同了</mark>
              - <mark style="background-color:#fce7f3;">想要在UI上方显示的物体放在Canvas而不是场景中</mark>
              - <mark style="background-color:#fce7f3;">从而实现物体Z轴位置在Image上/下方就可以在UI上/下方显示</mark>
                - 而覆盖模式没法实现这个效果
              - 两个摄像机渲染,这里的PlaneDistance意义不大了
        - `Plane Distance(平面距离)`
          - UI平面在摄像机前方的距离,控制UI平面和屏幕的距离
            - 类似2D项目通过设置物体Z轴更改显示顺序
            - 可以调整UI在物体的前后
        - `Sorting Layer和Order in Layer`
      - `WorldSpace(世界空间模式)`
        - UI作为3D物体渲染，可放置在场景中，受场景相机和光照影响
          - VR常用
        - `Event Camera（事件相机）`
          - 不设定事件相机UI就没法响应
          - 事件相机把屏幕点击转成世界空间射线，用来点 UI 按钮
  - `Canvas Scaler(画布分辨率自适应组件)`
    - 基本概念
      - 主要用于分辨率自适应<mark style="background-color:#fef3c7;">(并不负责位置,这个由RectTrans负责)</mark>
      - Game的Stats选项中可以查看分辨率等信息
      - Rec组件中可以看到宽高WH和缩放系数Scale
        - <mark style="background-color:#fde8e8;">宽高*缩放系数=屏幕分辨率</mark>
      - 分辨率自适应
        - 通过不同算法求出缩放系数,从而控制UI的缩放
        - 实现屏幕大UI大,屏幕小UI小,适配不同屏幕
    - 适配模式
      - `Constant Pixel Size(固定像素大小)`
        - 无论屏幕分辨率怎么变，UI像素尺寸固定不变
          - <mark style="background-color:#fde8e8;">不管屏幕分辨率,始终保持图片的原始尺寸</mark>
          - 游戏开发里用的少
        - `Scale Factor(缩放系数)`
          - 就是控制UI缩放嘛
      - `Scale With Screen Size(随屏幕尺寸缩放)`
        - 项目最常用，按参考分辨率做全屏自适应
        - `Reference Resolution(参考分辨率)`
          - 美术资源图的标准分辨率,所有匹配模式均会依照参考分辨率自适应计算
          - 一般就1920*1080
        - `Screen Match Mode(屏幕匹配模式)`
          - 分辨率比例不一致时(比如16:9和4:3),UI大小也会变化
          - `Expand:水平或垂直拓展画布区域`
            - 根据宽高比的变化来放大缩小画布,让UI尽量显示完整,可能有黑边
            - 公式
              - 缩放系数=Mathf.Min (屏幕宽 ÷ 参考分辨率宽,屏幕高 ÷ 参考分辨率高);
              - 画布尺寸 = 屏幕尺寸 ÷ 缩放系数
            - 举例
              - ![image-1](https://document-image.mubu.com/document_image/32569566_984bba84-0588-4adb-c4d9-82fa3953923c.png?x-tos-process=image/resize,w_400)

            - <mark style="background-color:#fde8e8;">反正知道个画布完整,但可能有黑边就对了</mark>
          - `Shrin:k水平或垂直裁剪画布区域`
            - 根据宽高比的变化来放大缩小画布，可能会裁剪
            - ![image-1](https://document-image.mubu.com/document_image/32569566_a30146be-e763-43ae-aa3a-632ad4207c3b.png?x-tos-process=image/resize,w_400)

            - <mark style="background-color:#fde8e8;">反正知道画布填充满整个画面,但可能有裁剪就对了</mark>
          - `Match Width Or Height:宽高或者二者的平均值作为参考来缩放画布`
            - 用的最多
            - `Matc(用于匹配的宽高匹配值)`
            - ![image-1](https://document-image.mubu.com/document_image/32569566_380edf66-5f5d-44fa-a21a-4ea84392c2bf.png?x-tos-process=image/resize,w_400)

              - 反正用对数只是为了更加准确
            - <mark style="background-color:#fde8e8;">只有这个表现效果需要记住</mark>
              - ![image-1](https://document-image.mubu.com/document_image/32569566_1b598d82-c10d-43dc-8d59-cec14609a8cf.png?x-tos-process=image/resize,w_400)
              - 缩放时UI元素大小不变
      - `Constant Physical Size(固定物理尺寸)`
        - ![image-1](https://document-image.mubu.com/document_image/32569566_0eeb9f15-0626-4712-f936-1766e6b58f96.png?x-tos-process=image/resize,w_400)
        - ![image-1](https://document-image.mubu.com/document_image/32569566_c31dc093-402d-4814-91f2-b175986a6ab8.png?x-tos-process=image/resize,w_400)
          - <mark style="background-color:#fef3c7;">一般用不上物理模式,知道这个区别就行</mark>
          - 总之就是不同DPI下保持图片大小仍然一样
        - `DPI：`图像每英寸长度内的像素点数
          - <mark style="background-color:#fef3c7;">手机屏幕小也能到1080p,就是因为DPI高</mark>
        - `Physical Unit：`物理单位，使用的物理单位种类
          - ![image-1](https://document-image.mubu.com/document_image/32569566_d5f9b3b1-2be0-4cc1-85f5-fefde83d868d.png?x-tos-process=image/resize,w_309)
        - `Fallback Screen DPI：`备用 DPI，当找不到设备 DPI 时用这个
        - `Default Sprite DPI：`默认图片 DPI
      - `World(3D世界模式)`
        - `Dynamic Pixels Per Unit(动态像素清晰度)`
          - 控制 UI 在 3D 空间里的清晰度(每个世界单位中的像素数量)
        - 世界Canvas固定这种模式
      - 通用选项
        - `Reference Pixels Per Unit(单位参考像素)`
          - 多少像素对应Unity中一个单位(默认一个单位100像素)
          - 和图片设置中的Pixels Per Unit一起参与计算
            - Sprite图片导入Image,点击下面的SetNativeSize
              - 图片WH就变成原始尺寸(也就是自带的像素大小),
              - 这个原始尺寸的计算公式如下:
            - 恒定像素计算公式
              - <mark style="background-color:#fde8e8;">UI 原始尺寸 = 图片像素 ÷ (Pixels Per Unit ÷ Reference Pixels Per Unit)</mark>
            - 图片设置中还有Pixels Per Unit,以及Canvas的Reference...,这里均为100
              - 100/100 =1,所以变成原有像素
            - <mark style="background-color:#fde8e8;">而在恒定像素模式下,不管屏幕分辨率,始终保持图片的原始尺寸</mark>
  - `Graphic Raycaster(射线事件交互组件)`
    - 图形射线投射器,主要用于控制位置和对齐方式
      - 基于图形而不是碰撞器
      - ![image-1](https://document-image.mubu.com/document_image/32569566_0ab48840-b958-4780-fbe4-81b51910fb5b.png?x-tos-process=image/resize,w_375)
    - `Ignore Reversed Graphics(是否忽略反转图形)`
      - 面板Canvas下Btn修改Z轴就是正常的平面旋转
      - 修改XY轴旋转就会翻转按钮Btn,这个就决定点击按钮背部是否还响应
      - 注意是忽略了反转图形才能点击
    - `Blocking Objects(阻挡物体类型)`
      - 覆盖渲染模式下无效(因为UI不可能被物体阻挡)
      - 默认不会被任何物体阻挡,即使有2D/3D物体挡在前面也能点击物体
    - `Blocking Mask(阻挡层级)`
      - 和上面这个配合使用,决定物体在哪些层级的时候才能阻挡
  - `RectTransform(UI对象位置锚点控制组件)`
    - 主要用于控制位置和对齐方式
- 依附于EventSystem的组件
  - `EventSystem(玩家输入事件响应系统组件)`
    - 主要用于监听玩家操作
    - <mark style="background-color:#fef3c7;">运行状态下,EventSystem可以查看右下角的输入调试信息</mark>
    - First Selected(初始选中对象)
      - 一开始就自动选中某UI控件
      - 就是手柄切换会默认跳到某个选项
    - Send Navigation Events(是否允许导航事件)
      - 手柄按上下左右就会切换选项而不需要鼠标移动上去
    - Drag Threshold(拖拽阈值)
      - 移动多少像素算拖曳(死区?)
  - `Standalone Input Module(独立输入模块组件)`
    - 主要用于监听玩家操作
      - ![image-1](https://document-image.mubu.com/document_image/32569566_b93c4c22-f3c1-49be-cda9-890d8fa44b2e.png?x-tos-process=image/resize,w_400)
    - `Horizontal Axis(水平轴)`
    - `Vertical Axis(垂直轴)`
    - `Submit Button(提交按钮)`
    - `Cancel Button(取消按钮)`
    - `Input Actions Per Second(每秒输入动作数)`
      - 额,防止连发宏?
    - `Repeat Delay(重复延迟)`
      - 手柄按住一下才开始切换选项按钮(何意味)
    - `Force Module Active(强制模块激活)`
      - 防止输入模块自动关闭以节省性能
  - `Touch Input Module(触摸输入模块)`
    - 老模块已经合并了,只有老版本看得见
